# Audit of phases 1-6 (2026-09-22)

Independent audit of commit `bcc937e` (end of Phase 6) against `PLAN.md`,
`CLAUDE.md` and the docs. Phases 1-6 were implemented by another agent. This
file holds the evidence; `PLAN.md` section 11 lists each item in one line and
section 8 schedules it.

## Method

- Baseline gates at `bcc937e`: 114 pytest, 3 vitest, 30 Playwright, production
  build all pass. Ruff: 21 errors, 15 files unformatted.
- Eleven audit dimensions, each writing and running its own probe tests in an
  isolated git worktree: phase 1 core, API/CLI, frontend functional, design
  system and accessibility, analysis engine, phase 6 features, security and
  privacy, real-data verification, docs and spec traceability, mutation
  testing, scale and robustness.
- Real-data check: read-only sync of the developer's real logs (69 files,
  6,775 responses) into a scratch store, compared against an independent
  parser that does not import ccburn. Store, `ccburn json` and `/api/summary`
  agree with it exactly, except where A-003 applies.
- Mutation testing: 95 mutants, 51 killed by the suite, 43 non-equivalent
  survivors (all test gaps; every survivor was then killed by a probe).
- Every critical and high finding was re-verified by an independent skeptic
  that reproduced it with its own probe. None was refuted. Medium and lower
  findings carry the original auditor's probe evidence but were not
  re-verified; each fix still starts with a failing test (`CLAUDE.md`).
- Online research (pricing page, Claude Code docs and changelog, competitor
  issue trackers) informed the new phases; see PLAN section 8, Phase 6.5.

## Totals

critical: 1, high: 6, medium: 55, low: 50, info: 16. Scheduled: Phase 6.5b: 17, Phase 6.5c: 25, Phase 6.5d: 8, Phase 6.5e: 26, Phase 6.5f: 23, Phase 6.5g: 20, Phase 7: 9.

## Claude desktop app cross-check

The desktop app's usage panel (Sessions 33, Messages 21,183, Total tokens 15M,
Active days 44, per-model In/Out) was reproduced exactly from the local
Claude Code transcripts as of 2026-09-15 19:13 JST, a week before the
screenshot. Its rules: every JSONL line summed with no dedup (subagent files
included), cache reads and writes excluded, messages counted as raw
user+assistant lines, sessions and active days counted from any user or
assistant line, Cowork excluded. Its token total is therefore about 2.7x the
deduplicated figure (14,964,413 vs 5,547,214 input+output at the same instant).
ccburn's deduplicated numbers are the correct ones, apart from A-003. Phase
6.5f adds an in-app reconciliation so the two can be compared directly.

## Details

### A-001 · history.json rollup permanently loses usage when a day is partially pruned (session spanning midnight, resumed/forked files)

- **Severity:** critical · **Category:** bug · **Built in phase:** 1 · **Scheduled:** Phase 6.5b
- **Verification:** confirmed (auditor probe + independent skeptic)
- **Spec:** PLAN.md 2.4 Retention; history.py module docstring
- **Where:** `ccburn/history.py:69`, `ccburn/history.py:98`, `ccburn/cli.py:163-165`, `ccburn/api/routes.py:98`
- **Expected:** PLAN 2.4: rollups are kept from the first run forward. Pruning a transcript must not reduce any day's stored totals.
- **Actual:** Any day still touched by a surviving file has its rollup replaced by that file's share only, permanently. The user works 8 PM-4 AM so sessions cross midnight almost daily; all-time and daily hero numbers undercount.
- **Evidence:** Probe test_history_prune_with_session_spanning_midnight: pruning older s2.jsonl gives 'Aug 1 input before 5100 after prune 100 total before 5200 after 200'. test_history_rollup_partial_prune_same_model_overwrites_blob: 'blob before 600 blob after 100'. merge() sets days[key] = live bucket for every live (day, model); restore() skips any live day, so a partial live view overwrites the complete stored row. /api/summary and /api/daily read build_report (live logs + history.json), not the SQLite turns table.
- **Repro:** uv run --no-sync pytest -q -p no:cacheprovider --basetemp=<bt> tests/probes_d1/test_d1_more.py::test_history_prune_with_session_spanning_midnight -s
- **Suggested fix:** Merge per response keyed by (msg_id, request_id), or build the headline from the SQLite turns table. At minimum never overwrite a stored day|model row with a smaller live bucket.

### A-002 · Restored history days show unknown-model usage as $0 and drop the unpriced flag

- **Severity:** high · **Category:** bug · **Built in phase:** 1 · **Scheduled:** Phase 6.5b
- **Verification:** confirmed (auditor probe + independent skeptic)
- **Spec:** CLAUDE.md non-negotiables; PLAN trap 4
- **Where:** `ccburn/history.py:25-28`, `ccburn/history.py:69-80`, `ccburn/history.py:101-106`
- **Expected:** CLAUDE.md: never price an unknown model at zero. A restored day keeps its unpriced count and unknown model names.

- **Repro:** uv run --no-sync pytest ... tests/probes_d1/test_d1_more.py::test_history_restore_turns_unpriced_into_zero_cost -s
- **Suggested fix:** Persist 'unpriced' in the rollup row (bump history SCHEMA); on restore set bucket.unpriced and add to report.unknown_models.

### A-003 · Dedup keeps the first (streaming placeholder) usage line, undercounting output tokens by 7.6% on real data

- **Severity:** high · **Category:** bug · **Built in phase:** 1 · **Scheduled:** Phase 6.5b
- **Verification:** confirmed (auditor probe + independent skeptic)
- **Spec:** CLAUDE.md non-negotiable 1; PLAN trap 1
- **Where:** `ccburn/sources.py:136`, `ccburn/store.py:316`, `CLAUDE.md:30-31`, `docs/DATA-SOURCES.md:18-19`, `tests/fixtures/claude_code_session.jsonl`
- **Expected:** Each response counted once with final usage (line with stop_reason, or max output_tokens).
- **Actual:** First line wins in both sources.load and store.sync_files; output tokens and cost understated.
- **Evidence:** Real logs: 406 of 6,871 responses have several same-key lines in one file with differing output_tokens, always increasing. First line is a streaming placeholder (commonly 8 or 3, stop_reason null). ccburn keeps first seen and loses 402,963 output tokens (7.6% of 5,332,651; $12.78). 332 of 406 in 2026-09. Store matches the first-seen oracle. Probe test_d7_streaming_placeholder.py fails: 'kept streaming placeholder output=8' (expected 612).
- **Repro:** python scratchpad/d7r_variants.py scratchpad/d7r_cutoff.txt, or run tests/probes_d7/test_d7_streaming_placeholder.py
- **Suggested fix:** Keep the row with max output_tokens or non-null stop_reason; compare against stored row in sync_files; add a placeholder+final fixture; fix CLAUDE.md/DATA-SOURCES wording.

### A-004 · CSRF: POST /api/harvest accepts a cross-origin text/plain body and writes fake sessions and costs to the store
